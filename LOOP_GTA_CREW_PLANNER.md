Source: the design decided with the user on 2026-11-03, recorded in `HORUS — Design Document v2.md`
("Crew, GTA gimbal and GTA route planner", diagram block Crew `#5c06`) and `PLAN.md` phase 7, plus

`/seref_manager run LOOP_GTA_CREW_PLANNER.md` or `/loop --until`) stops the loop only when the line
above reads `STATUS: DONE`, no `- [ ]` is left, every `- [x]` carries `DONE:`/`INVALID:` evidence and
every `- [!]` a `BLOCKED:` reason.

The phase in one paragraph: GTA gets a real gimbal (pitch and pan, measured attitude back to HORUS)
in place of ArduPilot's placeholder servo mount; the mod surveys the whole GTA map once at 5 m cells
into a top-surface height map; a drone board tool `plan_route` finds obstacle-free routes on it, at
one altitude or climbing over obstacles; and the AI pilot gains a crew: the planner, its own chat
with its own drone board role token, asked by the commander through `ask_planner`. The commander
keeps its flight tools (no pilot member yet) and stays the only agent that talks to the operator.

Facts the items rely on (checked 2026-11-03):
- Gimbal: HORUS is the gimbal manager over MAVLink gimbal-device v2 on `udpin:127.0.0.1:14600`
  (`horus/gimbal/link.py`); `device.py` (`GimbalDeviceEndpoint`) and `frames.py` are
  simulator-independent; `gazebo.py` is the only Gazebo-specific file and the pattern to copy.
  `look` reaches it through `HorusExecutor.look` (`horus/executor/core.py:729-765`), which sends yaw 0
  today. `GimbalSettings` already has `yaw_limit_deg` (`horus/config.py:30-71`).
- GTA camera: `PhysicsLink.CameraAxes` (`gta/horus_mod/src/Core/PhysicsLink.cs:170-182`) already
  turns pan, roll, tilt; the angles come from `GimbalServo` reading SITL servo channels 9-11
  (`PhysicsLink.cs:11-35`, `:123-138`) set by `MNT1_TYPE 1` / `SERVO9-11_FUNCTION` in
  `sim/scripts/start_gta_sitl.sh:52-55`; nothing reports the angle to HORUS. Existing mod channels:
  UDP 9002 SITL JSON, TCP 5610 frames, UDP 5612 `HRNG` ranges (`Core/RangeSensors.cs:124-150`,
  `horus/tof_bridge/gta.py`); 5611 was the removed pose receiver.
- Heights: no GTA data on disk has obstacle heights (navmesh vertices have z, but buildings are holes
  in it; object dumps are points). The mod casts rays with SHVDN `World.Raycast` (synchronous LOS
  probe, about 0.25 ms per ray, `gta/horus_mod/README.md:186-193`) and loads collision away from home
  with `SET_FOCUS_POS_AND_VEL` + `REQUEST_COLLISION_AT_COORD` (`HorusGtaScript.cs:575-608, 728-768`).
  Tile index NED bounds `[-6237.1, -4436.4, 8988.9, 7347.1]` (about 15.2 x 11.8 km). Home ground
  GTA z is about 29.69 (`gta/horus_mod/README.md:803`); HORUS `up_m` is measured from the resting body
  centre, 0.121 m above home ground (`HorusGtaScript.cs:255-259`).
- No path search exists anywhere in the repo; `goto(pose={north_m,east_m,up_m})` flies a straight
  line (`horus/executor/core.py:681-698`). `horus/maps` is standard library only (`model.py:12-13`).
- AI pilot: one `ClaudeCodeSession` per mission with the drone board as its only MCP server and a
  client-side tool filter (`horus/commander/backends.py:45-147`); the drone board has one bearer token
  `HORUS_MCP_TOKEN` (`horus/mcp_server/server.py:100-104`), so it cannot tell callers apart today.
