HORUS separates the **AI pilot** (`horus/commander/`) from the **AI model** so you can swap providers directly inside **HORUS Studio → Settings → AI Pilot & Crew** without editing YAML files.

## Supported providers

| Provider | How it connects | Credentials |
| --- | --- | --- |
| **Auto-detect** | Checks saved settings, then environment variables, then `claude` / `omp` CLIs | Any below |
| **OpenAI** | Official OpenAI Python SDK | `OPENAI_API_KEY` |
| **Anthropic** | Official Anthropic Python SDK | `ANTHROPIC_API_KEY` |
| **Google Gemini** | Gemini OpenAI-compatible endpoint | `GEMINI_API_KEY` |
| **OpenRouter** | OpenRouter OpenAI-compatible endpoint | `OPENROUTER_API_KEY` |
| **Ollama / Custom** | Any OpenAI-compatible base URL (default `http://127.0.0.1:11434/v1`) | Optional `CUSTOM_API_KEY` |
| **Claude Code CLI** | Persistent `claude` stream-json subprocess | Local `claude` login |
| **OMP CLI** | Persistent `omp --mode rpc` subprocess | Local `omp` login |

Secrets entered in HORUS Studio are written to `secrets.json` with `0600` permissions on POSIX and never returned in API responses (only masked hints are shown).

## Crew roles

HORUS supports specialized **Crew** members (starting with the route planner role) that receive scoped **Drone board** tokens so read-only planners cannot issue flight commands. See the [Architecture](/horus-drone/concepts/architecture/) guide for block boundaries.
